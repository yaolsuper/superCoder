# LIGHT 单轮执行

本协议只适用于单轮、低风险、范围小、无 BUG/事故/迁移和跨轮恢复的任务。它在一个 light-task.md 中保留输入、方案、范围、状态、review 与验证，不创建 Plan/MR、三文件 epoch、独立 validation 或 CP5。

## 开始与修改

1. 读取 artifact-root、artifact-model 和 advancement-mode，确认用户请求与允许路径；有关键业务未知项时先调查，不能用 LIGHT 绕过真实人工决策。
2. 使用 `../../superCoder/assets/templates/light-task.md`，记录来源、目标/非目标、当前事实、实施选择、允许/禁止路径和验收方式。仅请求分析或计划时止于相应小节，不修改产品代码。
   来源可为 spec.md、prd.md 或需求描述，记录文件/版本/条目或原始消息引用；不要求补齐产品文档，不将上游设计建议当成系统现状。没有真实结构变化时不加载完整架构模板。
3. 用户已授权当前完整任务时，在文件中记录该授权，不重复索要同一批准。未授权启动、或存在下一完整任务时，按推进模式处理。
4. 修改前核对目标明确、所需事实充分、路径合规、风险仍低、无阻塞和验证可执行。门禁结论写入同一文件；不运行仅适用于 STANDARD / CONTROLLED 的完整来源链、Task 设计或 CP 表。
5. 实施后检查实际 diff、必要注释和范围，做一次有界 review。记录问题、范围内修复与真实验证命令/结果；改动后旧验证失效，重跑受影响检查。

## 验收与升级

只有实际行为符合请求、review 无阻断项、当前代码验证通过时，才在 light-task.md 内记录 ACCEPTED 和最终业务结果。不要为了普通小任务创建独立需求摘要；未执行验证或验证失败时保留真实未完成状态。

范围扩大、风险变高、变更接口/数据/架构/依赖、出现未解释失败、需要跨轮恢复或发布/提交放行时，先升级 STANDARD / CONTROLLED。已有 light-task.md 作为来源证据引用，新增所需阶段产物，不声称旧轻量记录已经满足完整链路。

BUG 始终保留独立根因与回归证据要求，不属于 LIGHT。推进模式不降低风险模式。
