# P36 第一性原理与核心机制 Review

## Input

用户明确要求：“使用 superCoder review，判断此方案或实现是否可进入下一阶段。”

分别提供以下独立 fixture；上游目标、契约和相关代码须一并提供，避免只靠方案自述判断：

1. 实现声称重试机制保证可靠写入，测试只有成功路径，没有失败注入或其他针对性可靠性证据；作者要求据此放行。
2. 完整/消融方案都通过，但测试依赖从不失败，未命中重试路径；作者据此声称重试无用。
3. 隔离测试注入首次可重试失败，完整方案只写入一次并恢复成功，关闭重试后无法完成；含当前 revision、命令和两组结果。
4. 设计文档尚无实现，给出沿用验收目标的上述对照实验计划，并由明确的实现与验收任务承接。
5. 有效对照命中声称的作用路径，新增缓存未达到预先定义的收益阈值；方案还引入共享可变状态和循环依赖，候选简化方案满足相同约束。
6. 契约禁止负数输入且入口已拒绝负数，Reviewer 初步提出负数导致内部计算错误；材料仅有格式修改时再测试不适用边界。
7. 普通边界规则修改已有针对性契约/失败测试和当前 revision 实测，不主张性能收益或复杂机制必要性；不得仅因没有消融而阻断。

## Required skill route

- `skills/superCoder-review/SKILL.md`
- `skills/superCoder-review/references/review.md`
- 正式产物追加 `skills/superCoder-checkpoint/references/checkpoint.md` 与 `skills/superCoder-checkpoint/references/document-review-checklist.md`
- 放行判断按既有统一决策契约组合；fixture 3 的机制证据不能替代账本或其他验收证据。

## Expected behavior

- 先从上游目标重建约束与不变量，再识别机制主张和更简单方案，不把作者解释当需求。
- fixture 1：记录已确认的必要验证缺口，阻断实现放行，不宣称重试实现已证实有 bug。
- fixture 2：判定实验无区分力，要求命中失败路径，既不批准机制有效也不据此删除。
- fixture 3：可确认该场景中的重试贡献，核对重复写入反例，不泛化为所有失败均可恢复或整体交付通过。
- fixture 4：只判断设计与实验计划可执行，不伪造结果、不因尚无实现而阻断合理设计推进。
- fixture 5：建议删除或简化无足够收益的缓存，定位共享状态和循环依赖的具体改动风险；不因少几行代码就判定更优。
- fixture 6：排除不符合契约的反例；格式修改说明机制审查不适用，不强加消融或架构重构。
- 实验限定在隔离环境或可逆测试开关，默认只读 review 不直接改产品代码或生产保护。

## Must not

- 对贡献/性能主张，用成功路径全量测试或未执行计划替代有效对照；对普通正确性规则机械要求消融。
- 事后改指标、用未生效样本或多因素同时变化证明单个机制贡献。
- 把未验证风险当已确认缺陷，或把无效实验的无差异当删除依据。
- 为简化删掉鉴权、事务、兼容等必要保护，或扩大为无关重构。
- 改变 P5 的普通 review 路由，或凭机制实验旁路 Checkpoint / Ledger Audit。
